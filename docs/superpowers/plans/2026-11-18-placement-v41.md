# 카드 배치 v4.1 구현 계획 (구간 지키기 · 금액 비례 교체 · 1장 · ① 구간 가치 순 · 일정 팝업)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설계서 v4.1과 방식 ① 순서 변경을 `solpay-ai` 엔진·API, `demo`에 구현하고, 재생으로 실행과 수치를 확인한다.

**Architecture:**
- 새 결정 경로를 `ranker.decide` 안에 `params.engine == "v4"`로 둔다. 기존 경로는 `engine="v3"`로 남긴다.
- 일정 팝업(카드 추천·프로모션 추천)은 새 모듈 `engine/popup.py`에 둔다.
- 프로모션 카드는 `PlacementEngine.rank_state`에서 사용자 규칙 다음, 3~6단계 전에 적용한다.

**Tech Stack:** Python 3.13, FastAPI, pytest, uv. 데모는 FastAPI와 바닐라 JS.

**Spec:** `docs/superpowers/specs/2026-11-17-placement-algorithm-redesign-design.md` (= `PayMate 카드 배치 알고리즘 설계서_v4.1 일정 팝업 반영.docx`) + 방식 ①을 구간 가치가 큰 카드부터 채우기

## Global Constraints
- 데이터를 바꾸지 않는다. 대상: `data/`, `카드서비스_DB*`, `artifacts/`의 모델·priors. 프로모션은 `data/config/promotions.yml`을 읽기만 한다.
- 데모 실행 확인 때 전략 저장소는 `SOLPAY_STRATEGY_DB`를 임시 폴더로 돌린다.
- 커밋하지 않는다(사용자 요청 시에만).
- 금액 문구는 엔진 계산값만 쓰고, 소비를 늘리라는 표현은 쓰지 않는다.
- 위치(GPS)는 받지 않는다.

## Review Focus
- **신한카드가 없는 사용자:** 프로모션 추천과 프로모션 카드가 없어야 한다. → Task 4 테스트
- **프로모션 카드가 제외 규칙에 걸린 경우:** 다음 신한카드를 쓰고, 고정 규칙이 있으면 고정 카드를 쓴다. → Task 5 테스트
- **일정 시간대에 같은 업종 결제가 이미 있는 경우:** 프로모션 카드를 끄고 평소 계산으로 돌아간다. → Task 5 테스트
- **구간이 없는 카드·지난달 이력이 없는 사용자:** 교체 기준이 0원이고 오류가 나지 않아야 한다. → Task 2 테스트
- **일정이 끝난 뒤 팝업을 다시 열 때:** 지난 일정은 프로모션 후보에서 빠져야 한다. → Task 4 테스트

### Task 2: v4 결정 (구간 지키기 · 금액 비례 교체 · 즉시 혜택 점수 · 1장)

**Files:**
- Modify: `solpay-ai/engine/perf_value.py`, `solpay-ai/engine/ranker.py`
- Test: `solpay-ai/tests/test_v41.py`

**Interfaces — Produces:**
- `perf_value.switch_threshold(state, plan, budget, user_card_id: int, amount: float) -> float`
  - 다음 구간 기준: `min(a, N) × G × p ÷ N`
  - 다음 구간이 없거나 N ≤ 0 또는 G ≤ 0이면 0
- `Decision`에 필드 추가: `threshold: float = 0.0`, `hold: bool = False`

**decide (engine == "v4")**
- 기본 카드는 `choose_base_card`(구간 지키기 포함)로 정한다. `hold`는 `_hold_tier` 결과와 같은지로 판단한다.
- 점수는 `score_cards(..., params.with_(w2=0, w3=0), promotions=[])`의 `total`이다. 즉시 혜택만 들어간다.
- 교체 기준은 `switch_threshold × params.w2`다. w2는 성향 규칙이 0.5~1.5로 바꾼다.
- 교체 조건: `gain > 교체 기준`이고, `근거 확률 ≥ evidence_prob`이거나 반복 구간이다.
- 2순위는 None이다. `max_display ≥ 2`일 때만 기존 `_second_card`를 쓴다.

- [ ] 테스트 `test_교체_기준은_기본_카드의_실적_가치다`: 설계서 6단계 예시 값으로 확인한다. N=120,000, G=9,600, B=300,000, σ=100,000, a=6,700 → 515 ± 1원
- [ ] 테스트 `test_구간이_없거나_이미_채웠으면_교체_기준은_0원`

### Task 4: 일정 팝업 모듈

**Files:**
- Create: `solpay-ai/engine/popup.py`
- Modify: `solpay-ai/engine/loader.py` (`load_popup_promotions`), `solpay-ai/engine/recommend.py` (`regular_recommendation` 분리), `solpay-ai/pyproject.toml` (pyyaml을 실행 의존성으로)
- Test: `solpay-ai/tests/test_popup.py`

**Interfaces — Produces:**
- `loader.load_popup_promotions(catalog, path: Path | None = None) -> list[Promotion]`
  - 경로는 `SOLPAY_POPUP_PROMOTIONS`, 없으면 `../data/config/promotions.yml`
  - 카드사는 SHINHAN, `needs_check`는 그대로 둔다.
- `recommend.regular_recommendation(state, payments, history, at, params) -> Recommendation | None`
  - 기존 '정기' 규칙(월 이득 ≥ `recommend_min_monthly`, 30일 안 같은 카드 제외)이다. 간격 확인은 부르는 쪽이 한다.
- `popup.PromotionOffer` (frozen dataclass)
  - 필드: item_id, start, end, category, amount, promotion_id, brand, title, kind, user_card_id, card_id, card_name, promo_value, card_value, alternatives
  - `total` = promo_value + card_value
  - alternatives = 다른 신한카드의 (user_card_id, total), 큰 순서
- `popup.promotion_offers(state, schedules, promotions, at, params) -> list[PromotionOffer]`
  - 남은 일정(끝 + tail ≥ at)마다, 일정 시작 시각에 진행 중이고 그 업종에 가맹점이 있는 행사(needs_check 제외)를 찾는다.
  - 각 행사에서 받을 금액이 가장 큰 신한카드 하나를 골라 total이 큰 순서로 돌려준다.
- `popup.schedule_popup(state, payments, schedules, history, promotions, at, params) -> dict`
  - `{"kind": "card"|"promotion"|"none", "recommendation": Recommendation|None, "offers": list[PromotionOffer]}`
  - 카드 날짜: 마지막 카드 추천에서 3일 이상 지났거나 추천한 적이 없음
  - 카드 날짜에 추천할 카드가 없으면 프로모션으로 넘어간다.
  - 프로모션은 최대 `popup_promotions`건이다.
