# 일정 '직접 입력' 업종·가맹점 자동 분류 설계 (2026-11-23)

## 왜 만드나

하루 일정의 직접 입력칸에 "스타벅스"라고 써도 지금은 '기타' 일정으로만 저장되고, 카드·프로모션 추천에 쓰이지 않는다.
재생 평가에서 업종을 미리 알면 혜택률이 1.255% → 1.452%로 오르고, 예측 손해의 56%가 백화점·헬스앤뷰티처럼
앱의 13개 업종 묶음(🛍 쇼핑)으로는 구분되지 않는 업종이었다. 사용자가 쓴 말을 AI 가 업종·가맹점으로 바꿔 주면
일정이 더 많이, 더 정확하게 들어오고, 대회에서 보여 줄 AI 활용도 생긴다.

## 사용자 결정 (2026-11-23)

| 항목 | 결정 |
|---|---|
| 입력 범위 | 가게 이름·짧은 말 ("스타벅스", "헬스장", "친구랑 저녁"). 시간은 지금처럼 고른다 (하루 일정 문장 해석은 하지 않음) |
| 붙이는 곳 | AI 서버 API + 결제 데모(`demo/`)의 "오늘 일정을 알려주세요" 화면. 통합 앱은 Spring 연결 때 |

## 목표 / 하지 않을 것

- 목표: 짧은 말 → (업종, 브랜드) 분류 API, 일정에 브랜드 저장, 브랜드를 반영한 카드·프로모션 추천, 결제 데모에서 입력→확인→추천 시연, 정확도 평가.
- 하지 않을 것: 문장에서 시간·여러 일정 뽑기, 통합 앱(Expo) 화면, Spring 연동, 지점(위치) 수준 분류, 입력 원문 저장.
- 실패로 보는 것: 확신 없이 틀린 브랜드를 붙이는 것(안 붙이는 것보다 나쁘다), 목록에 없는 업종을 만들어 내는 것, 원문이 로그·DB 에 남는 것.

## 방식 (사실상 하나)

| 방식 | 판단 |
|---|---|
| **가맹점 검색 먼저 → 못 찾으면 OpenAI (채택)** | 브랜드 이름·별칭은 검색이 즉시·정확·무료로 찾고(스벅→스타벅스, 메가커피→메가MGC커피), 일반 말은 OpenAI 가 업종을 고른다 |
| 검색만 | "헬스장", "친구랑 저녁"을 못 찾는다 (확인함). AI 활용도 아님 |
| OpenAI 만 | 매번 1~3초·비용, 브랜드를 잘못 붙일 위험 |

## API

`POST /internal/places/classify` (토큰 검사 같음)

```json
요청 {"text": "스벅", "user_id": 1, "at": "2026-11-05T12:00:00+09:00"}
응답 {"category": "CAFE", "category_name": "카페/커피전문점", "brand": "스타벅스", "brand_name": "스타벅스",
      "source": "search | llm | none", "candidates": [{"category": "...", "brand": "..."}],
      "amount_hint": 6500, "ms": 12}
```

- 순서: 정리(앞뒤 공백, 40자 자르기, `privacy.redact`) → `find_merchants`(별칭 포함) → `find_categories` → 둘 다 없으면 OpenAI.
- 검색이 한 브랜드로 딱 맞으면(정확 일치·별칭·브랜드 일치) `source=search`. 부분 일치로 여러 브랜드면 `candidates` 에 넣고 브랜드는 비운다.
- "백화점"처럼 업종 이름뿐이면 업종만, 브랜드는 null (엔진이 지금처럼 그 사람이 평소 간 브랜드로 추측).
- `amount_hint`: `user_id` 가 있으면 그 사람의 최근 90일 그 브랜드(없으면 그 업종) 결제 중앙값, 없으면 전체 사용자 중앙값.
- 사용자 번호·원문은 응답 기록 외에 남기지 않는다 (로그에도 원문 없음).

### OpenAI 분류 (검색 실패 때만)

- `OPENAI_MODEL`(기본 gpt-4o-mini), Chat Completions json_schema, temperature 0, 제한 시간 `PLACE_CLASSIFY_TIMEOUT_SEC` 기본 5초.
- 출력 `{"category": <결제화면 대상 업종 코드 enum 또는 "UNKNOWN">, "brand": <카탈로그 브랜드 목록 중 하나 또는 null>, "confidence": "high|low"}`.
  카탈로그 브랜드 목록(153개)을 사실로 준다 → 오타("스타벅쓰")도 잡는다. 목록 밖 브랜드는 null 로 바꾼다.
- `confidence=low` 거나 UNKNOWN 이면 `category` 를 비우고 `candidates` 에 OpenAI 후보만 둔다 (사용자가 고르게).
- 실패·시간 초과·키 없음 → `source=none` (사용자가 업종을 직접 고른다).
- 같은 글자는 서버 메모리에 결과를 둔다 ("헬스장"을 여러 사람이 써도 OpenAI 한 번).
- 업종 enum 은 일정에 넣을 수 있는 업종(지금 `put_schedule` 이 받는 `catalog.category_names` 중 `ALL` 제외)과 같게 한다.
  브랜드를 프로모션 계산에 쓸 때는 (브랜드, 업종)의 대표 가맹점으로 잇는다 (팀 DB 결제와 같은 규칙, 빌더가 정함).

## 일정에 브랜드 저장

- `ScheduleItem` 에 `brand: str | None = None` 추가. `PUT /internal/users/{id}/schedules/{day}` 의 항목에 선택 칸 `brand` (카탈로그에 없으면 422).
- DB 저장소의 `app.schedules` 암호문 payload 에 brand 포함, CSV·parquet 저장소도 같게. 브랜드는 위치가 아니므로 최소 수집 원칙 안 (지점·원문은 저장 안 함).
- 일정 응답(GET/PUT)에 brand 를 돌려준다.

## 브랜드를 반영한 추천

- 결제 화면 배치(`scenarios.build` 일정 분기): 일정에 브랜드가 있으면 그 시나리오의 브랜드 확률을 {그 브랜드: 1} 로 (없으면 지금처럼 brand_mix).
- 맞춤 추천 페이지(`page.py`): 카드 탭 계산과 가맹점(프로모션) 탭이 일정 브랜드를 쓴다 (없으면 지금처럼 평소 브랜드 추측). 프로모션은 그 브랜드에 걸리는 행사를 먼저.
- 일정 팝업(`popup.py`)도 같은 규칙.

## 결제 데모

- "오늘 일정을 알려주세요" 각 줄에 "가게 이름" 입력칸을 더한다. 입력을 멈추면(0.4초) 분류 API 를 부르고 아래에 칩을 보여 준다.
  ```
  [ 14:00 ] ~ [ 15:00 ]  [ 스벅            ]
                          → ☕ 카페/커피전문점 · 스타벅스   (AI 분류 · 바꾸기)
                          [ 카페/커피전문점 ▾ ]  [ 6,500 원 ]
  ```
  업종 선택은 분류 결과로 바뀌고, 사용자가 바꾸면 그 값을 쓴다. 금액은 `amount_hint` 로 채운다. `source` 를 작게 보여 준다(검색/AI).
- 저장하면 데모 서버가 brand 를 AI 서버로 넘긴다.
- 일정 다음 화면은 지금 `schedule-popup` 대신 **맞춤 추천 페이지**(`/recommendation-page`, 카드 탭 + 가맹점 탭)를 보여 준다. (내 판단, 아래 확인 필요)
- `/dev` 시험 화면에도 분류 시험 입력칸 하나.

## 확인 방법

- 자동 테스트: 검색 일치·별칭·부분 일치 후보·업종 이름만·OpenAI 가짜 응답(목록 밖 브랜드 → null, UNKNOWN, 시간 초과)·redact·40자·캐시,
  일정 brand 저장·조회·검증(DB 포함), 브랜드 있는 일정의 배치·추천 페이지 결과, 데모 API.
- `evaluation/place_eval.py`: 정답을 단 60개 표현(브랜드 20·별칭/약칭 10·오타 10·일반 말 15·애매/모름 5)을 실제 OpenAI 로 →
  업종 정확도, 브랜드 정확도, 틀린 브랜드를 붙인 수(0이 목표), OpenAI 호출 비율, 응답 시간.
- 결제 데모에서 "스벅" → 카드·프로모션 추천까지 브라우저로 확인.

## 내가 정한 것 (사용자 확인 필요)

1. 일반 말("백화점")은 업종만, 브랜드는 비운다 (엔진이 평소 브랜드로 추측).
2. OpenAI 에도 카탈로그 브랜드 목록을 줘서 오타·변형을 잡되, 목록 밖이면 버리고, 확신이 낮으면 후보만 보여 준다.
3. 결과는 칩으로 보여 주고 사용자가 바꿀 수 있다 (자동 확정 아님).
4. 금액은 그 사람의 그 브랜드(없으면 업종) 결제 중앙값으로 미리 채운다.
5. 결제 데모의 일정 다음 화면을 지금 일정 팝업에서 맞춤 추천 페이지(카드 + 가맹점 탭)로 바꾼다.
6. 같은 글자 분류 결과는 서버 메모리에 둔다 (비용 절약).
