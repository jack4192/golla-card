# 챗봇 고도화 1단계 설계 (2026-11-24)

검토 문서: `~/Downloads/신한커리어넥스트/SOLPay_챗봇_고도화_검토_2026-11-24.md` (4절 질문 목록, 5절 자세한 설명, 6절 단계).

## 왜

사용자 요청: "기본적으로 지금보다 더 자세히 답하되, 더 자세한 답을 원하면 '자세히'를 입력하게." 그리고 1단계의 나머지(계산 근거, 카드 용어, 프로모션 기간, 표가 안 보이는 문제 A안, 평가)는 그대로.
조사에서 나온 사실: 앱(PaymentBenefitChat.js, 홈 챗봇)은 응답의 `reply`·`rule_draft` 만 쓰고 `blocks`(표)는 그리지 않는다. 지시문의 "표가 화면에 따로 보인다"는 틀렸고, 검사 두 번 실패 때의 "아래 표를 확인해 주세요"는 빈 답이 된다.

## 결정 (사용자)

- 자세히 모드를 '물을 때만'으로 하지 않는다. **기본 답을 지금보다 자세히** (2~4문장 → 3~6문장, 이유를 도구 숫자로).
- 사용자가 **'자세히'** 를 입력하면 더 자세히 (6~10문장, 줄바꿈으로 2~3문단, 결론 → 근거 숫자 → 계산 과정 → 할 수 있는 것).
- 표가 안 보이는 문제는 우선 A안(AI 서버에서 문장으로). 앱이 표를 그리는 안은 따로 보여 주고 사용자가 판단.

## 내가 정한 것 (바꾸기 쉬움)

- '자세히' 알아채기: 질문에 '자세히'·'자세하게'가 있으면. '자세히'만 따로 오면(예: "자세히", "더 자세히 알려줘") 바로 앞 질문을 자세히 다시 답한다 (도구를 다시 불러 숫자를 얻는다).
- 안내 문장 "더 자세한 설명이 필요하면 '자세히'라고 입력해 주세요."를 코드가 대화에서 **한 번만** 붙인다 (도구를 쓴 보통 답, 지난 대화에 이 안내가 없을 때). 숫자가 없어 검사와 무관.
- 계산 근거: 결제 추천·다른 카드 비교 도구가 카드마다 `applied`(혜택 이름, 할인율·정액, 건당 최대, 최소 결제액, 한도 적용 전 금액)를 돌려준다. `evaluate_payment(detail=True)` 일 때만 붙여 기존 API 응답은 그대로.
- 카드 용어: 지시문에 숫자 없는 짧은 용어집 (숫자 검사에 걸리지 않게).
- 프로모션 기간: `list_promotions(ending=this_week|7days|this_month)`, 날짜는 코드가 계산.
- 검사 두 번 실패 답: "아래 표를 확인해 주세요" 대신 마지막 도구 결과로 만든 정해진 요약 문장 (카드 비교·점수표·실적·혜택표·새 카드·프로모션). 만들 수 없으면 지금의 "확인할 수 없는 내용이 있어…".

## 확인

- 시험: 자세히 알아채기·뒤따르는 '자세히'·안내 한 번·요약 문장·applied·기간 거르기.
- 평가 세트: '자세한 설명' 6, '카드 용어' 4, '프로모션 기간' 2 추가, '카드 등록' 기준 말을 ('카드 등록', '카드 신청')으로. 보통 답·자세히 답의 평균 문장 수를 함께 잰다.

- 사용자 결정 "자세히 별로다, 전부 빼기": '자세히' 입력으로 길게 답하기, 안내 문장, 버튼을 모두 뺐다. 기본 답 3~6문장과 계산 근거·용어·프로모션 기간·요약 문장·앱 표 표시는 그대로.
