# 연말 결산 화면 다시 만들기 — 설계서 (2026-11-23)

## 왜 바꾸나

홈의 '올해 카드 결산' 타일을 누르면 열리는 연말 결산 화면(`frontend/components/YearEndReport.js`)이 다음과 같은 상태다.

- 맨 위 '아낀 금액'은 서버 결제가 아니라 이 기기에서 맞춤 추천 화면을 볼 때 남긴 예상값(`utils/savingsRecords.js`, AsyncStorage)이다. 그래서 1년치 결제가 있는 시연 계정도 +0원으로 나온다.
- '그때 카드를 만들었다면?' 시트도 같은 기기 기록을 쓴다. 만들어 둔 연말정산 AI(놓친 혜택, `/api/ai/missed-benefit`)는 앱 어디에서도 부르지 않는다.
- 사용자 평: 인터페이스와 문구가 별로다.

목표: 올해 **실제로 받은 혜택**과, AI가 계산한 **놓친 혜택**(그 신한카드가 있었다면 더 받았을 금액)을 한 화면의 결산 리포트로 보여 준다.

## 사용자 결정 (2026-11-23)

1. **맨 위는 받은 혜택, 그 아래 놓친 혜택.**
   - 받은 혜택은 AI가 다시 계산하지 않고 결제 표에 기록된 금액을 더한다(카드 혜택 `benefit_amount` + 가맹점 행사 `promotion_amount`). 홈 '최근 결제'에 보이는 혜택과 숫자가 같아진다.
   - 사용자가 처음 고른 안은 'AI가 새로 계산'이었다. 기록이 모든 결제에 채워져 있다는 것을 확인하고 알린 뒤 이 방식으로 진행했다.
2. **기간: 올해 1월 1일부터 기준 시각까지.** 받은 혜택과 놓친 혜택이 같은 기간을 쓴다. 놓친 혜택 계산에서 전년 12월 결제는 1월의 전월 실적을 알기 위해서만 쓴다.
3. **놓친 혜택이 1만 원 미만인 카드는 숨긴다.** 남는 카드가 없으면 '지금 카드 조합이 잘 맞아요' 안내를 보여 준다.
4. **화면 짜임은 A안(리포트형):** 받은 혜택 → 혜택을 많이 준 카드 → 놓친 혜택(1위는 크게, 2·3위는 작게) 순서다.
5. **만드는 방법은 방법 1:** 받은 혜택은 백엔드가 결제 표에서 더하고, 놓친 혜택은 AI 엔진이 계산한다. 앱은 두 API를 동시에 부른다.

이전 결정 중 그대로 지키는 것 (2026-11-19, 메모리 project-missed-benefit):

- 놓친 혜택 후보는 가지지 않은 신한카드이고, 상위 3장을 보여 준다. 연회비는 기간만큼 뺀다.
- '바꾸기'와 '함께 쓰기' 두 가정 중 금액이 큰 쪽을 쓴다.
- 문장은 엔진의 정해진 틀이다: "그때 {바꾼 카드} 대신 이 카드를 쓰셨다면 / 이 카드를 발급받으셨다면 {N개월|1년} 동안 {금액}원을 더 받으셨어요". OpenAI는 쓰지 않는다.

## 목표 · 비목표 · 하면 안 되는 것

**목표**

- 시연 계정 test1~5에서 받은 혜택과 놓친 혜택이 실제 숫자로 보인다.
- AI가 느리거나 꺼져 있어도 받은 혜택 부분은 먼저, 정상으로 보인다.
- 문구는 쉬운 해요체로 쓴다. 숫자와 놓친 혜택 문장은 서버가 준 그대로 쓴다.

**비목표**

- 세금 연말정산(소득공제) 계산.
- OpenAI 문장 생성.
- 기기 기록(`savingsRecords.js`)과 그것을 쓰는 맞춤 추천 화면의 기록 코드 지우기. 이 화면이 더는 읽지 않을 뿐이다.
- DB 표 바꾸기, 공용 RDS 작업.

**하면 안 되는 것**

- 받은 혜택이 홈 '최근 결제'와 다른 숫자가 된다.
- 기준 시각 이후의 가상 결제(데이터에는 2026-11-26까지 있다)가 합에 들어간다.
- AI 실패 때문에 화면 전체가 비거나 멈춘다.
- 앱이 엔진의 숫자나 문장을 다시 계산하거나 바꿔 쓴다.

### 부분별 규칙과 문구

**머리**

- 제목: '연말 결산'.
- 큰 제목: '{연도}년 카드 결산'. 연도는 백엔드가 준 기간의 연도다.
- 기간 줄: '{M}월 {D}일 ~ {M}월 {D}일 · 결제 {N}건'.

**받은 혜택 카드**

- 큰 숫자는 total(= 카드 혜택 + 가맹점 행사)이다.
- 아래 줄은 '카드 혜택 X원 · 가맹점 행사 Y원'이다. Y가 0이면 '카드 혜택 X원'만 쓴다.
- 막대는 1월부터 이번 달까지 달마다 하나씩, total 기준이다. 가장 큰 달을 진하게 칠한다.
- 그 아래 한 줄: '가장 많이 받은 달은 {M}월, {금액}원이에요'.
- 올해 결제가 없을 때: '올해 결제가 아직 없어요' 안내를 보여 주고, 혜택을 많이 준 카드와 놓친 혜택 부분은 숨긴다.

**혜택을 많이 준 카드**

- 내 카드별 total 상위 3장을 보여 준다. total이 0인 카드는 뺀다.
- 카드 그림은 앱 카드 목록(`CARD_CATALOG_40`)에서 이름으로 찾는다. 없으면 기본 아이콘을 쓴다.

**놓친 혜택**

- 머리: '이 카드였다면 더 받았어요'와 'AI 분석' 꼬리표.
- 1위:
  - 카드 그림, 카드 이름, '+{gain}원', 엔진 `message`.
  - 꼬리표: swap이면 '{replaces} 대신', add이면 '지금 카드에 더해서'. 그리고 '연회비 {annual_fee × months / 12}원 빼고 계산'. 연회비가 0이면 연회비 꼬리표는 쓰지 않는다.
- 2·3위: 한 줄씩 '{순위}위 {카드 이름} +{gain}원'이다. 누르면 펼쳐져 1위와 같은 문장과 꼬리표, '카드 보러 가기'가 보인다.
- '카드 보러 가기'는 `officialProduct(code)`가 주소를 줄 때만 보여 주고, 누르면 그 주소를 연다. 맞춤 추천 화면과 같은 방식이다.
- 불러오는 중: 'AI가 올해 결제를 다시 계산하고 있어요'와 돌아가는 표시.
- 실패: '놓친 혜택을 불러오지 못했어요'와 '다시 시도' 버튼. 받은 혜택 부분은 그대로 둔다.
- 결과가 비었을 때(1만 원 이상이 없음): '지금 카드 조합이 잘 맞아요' / '올해 결제로 계산해 보니 1만 원 넘게 더 주는 신한카드가 없었어요.'

**계산 기준 (접었다 펴기, 처음에는 접힘)**

- '받은 혜택은 결제할 때 기록된 카드 혜택과 가맹점 행사 금액을 더한 값이에요.'
- '놓친 혜택은 AI가 올해 결제는 그대로 두고, 그 카드가 있었다면 매장 결제에 어떤 카드를 냈을지 다시 골라 계산한 값이에요. 전월 실적은 달마다 다시 세고, 연회비는 기간만큼 뺐어요.'
- '"대신"은 가진 카드 하나를 그 카드로 바꿨다고 본 금액이고, "더해서"는 지금 카드에 그 카드를 더해 함께 썼다고 본 금액이에요.'

**홈 타일 설명**

- '추천 카드로 얼마나 아꼈는지, 놓친 혜택은 얼마인지 확인해요'를 '올해 받은 혜택과 놓친 혜택을 확인해요'로 바꾼다.

**보이는 방식**

- 지금 화면처럼 전체 화면 Modal을 쓴다. 너비는 최대 640, 색은 앱의 남색·파랑 계열을 따른다.
- 받은 혜택 카드는 강조색 바탕으로 칠하고, 나머지는 흰 카드로 둔다.

## 엔진 (solpay-ai, 브랜치 ai/placement-engine)

`GET /internal/users/{user_id}/missed-benefit`에 `start: date | None`를 더한다.

- **start가 있을 때**
  - 계산 기간은 [start 00:00, at)이다.
  - start가 속한 달의 전달 1일부터 start 전까지의 결제는 전월 실적을 쌓는 데만 쓴다.
  - 전달 결제가 하나도 없어도 start가 속한 달부터 센다(그 달은 전월 실적 0에서 시작). months는 start가 속한 달부터 at이 속한 달까지의 달 수다.
  - 예: start=2026-01-01, at=2026-11-23 → months=11, 문장 '11개월 동안'.
- **start가 없을 때:** 지금처럼 days(기본 365)를 쓴다. 기존 동작은 바뀌지 않는다.
- **숨기는 기준:** 결과에서 gain이 `params.missed_min_gain`(기본 10000) 미만인 카드를 뺀 뒤 상위 3장을 고른다. 지금의 `gain > 0` 대신이다. days 경로에도 같이 적용한다. 이 API를 부르는 곳은 앱 화면과 개발 콘솔뿐이다.
- `recommend.missed_benefit`에 '어느 달부터 셀지'를 받는 선택 인자를 더한다. 기본값은 지금처럼 첫 달을 준비 달로 쓰는 것이다. 맞춤 추천 페이지(`engine/page.py`)의 호출과 결과는 바뀌지 않아야 한다.
- 응답 모양은 지금과 같다: card_id, card_name, gain, months, annual_fee, basis, replaces_user_card_id, replaces, message.

## 백엔드 (solpay-final, 브랜치 final)

**받은 혜택: `GET /api/payments/year-summary` (로그인 필요)**

- 기간은 기준 시각(`DemoClock`, `ai.fixed-at`이 있으면 그 시각)이 속한 해의 1월 1일 00:00부터 기준 시각까지다. 홈 '최근 결제'와 같은 시계, 같은 '내 카드' 조건(`user_cards.user_id`)을 쓴다.
- 응답:
  ```json
  {
    "year": 2026, "from": "2026-01-01", "until": "2026-11-23T14:05:00",
    "count": 1633, "benefit": 533440, "promotion": 7000, "total": 540440,
    "months": [{"month": "2026-01", "count": 152, "benefit": 54330, "promotion": 0, "total": 54330}, ...],
    "cards":  [{"userCardId": 2, "cardName": "…", "count": 400, "benefit": 300000, "promotion": 0, "total": 300000}, ...]
  }
  ```
- `months`는 1월부터 기준 시각의 달까지 빠짐없이 넣는다(결제가 없는 달은 0). `cards`는 total이 큰 순서로 정렬하고, 결제가 없는 카드는 넣지 않는다.
- 혜택·행사가 null인 결제는 0으로 센다.

**놓친 혜택: `GET /api/ai/missed-benefit`에 `thisYear=true` 선택 인자를 더한다**

- thisYear=true이면 백엔드가 `start = ai.today()가 속한 해의 1월 1일`을 엔진에 넘긴다. days는 넘기지 않는다.
- 인자가 없으면 지금처럼 동작한다.
- 응답은 엔진 JSON 그대로 돌려준다.

## 앱 (solpay-final/frontend)

- `api.paymentsYearSummary()`와 `api.aiMissedBenefit({ thisYear: true })`를 더한다. AI 호출 제한 시간은 기존 AI 상수를 따른다.
- 화면 계산은 순수 함수 파일 `utils/yearEndCore.js`에 두고 `node --test`로 시험한다. 담는 것:
  - 기간 줄 만들기
  - 가장 많이 받은 달
  - 막대 높이 비율
  - 카드 혜택·가맹점 행사 줄
  - 놓친 혜택 꼬리표(대신/더해서, 연회비 금액)
  - 카드 목록 찾기
  - 상태(불러오는 중/실패/비었음/있음) 고르기
- `YearEndReport.js`를 새로 짠다.
  - 열릴 때마다 두 API를 동시에 부른다.
  - 받은 혜택이 오면 바로 그린다. 놓친 혜택은 따로 상태를 둔다.
  - 서버 모드가 아니면(`SERVER_MODE=false`) '서버에 연결하면 결산을 볼 수 있어요' 안내만 보여 준다.
- `MainScreen.js` 타일 설명 한 줄을 바꾼다.

## 시험

- **엔진:** start 경로의 months와 문장('11개월 동안'), 전달 결제가 없을 때, 1만 원 기준(9,999원은 빠지고 10,000원은 남음), days 경로가 그대로인지, page.py 결과가 그대로인지. 엔진 전체 테스트를 통과해야 한다.
- **백엔드:**
  - year-summary 단위 시험(합, 빈 달 0, 카드 정렬, 기준 시각 이후 제외).
  - 로컬 DB 통합 시험(PaymentApiTest 방식, `ai.fixed-at` 고정).
  - AiService가 thisYear일 때 start를 넘기는지.
  - 백엔드 전체 테스트를 통과해야 한다.
- **앱:** yearEndCore 단위 시험. 브라우저(8081)에서 test1로 화면을 확인하고, AI를 끈 상태와 test4(1장만 남음)도 확인한다.

## 검토 뒤 정한 것 (만드는 사람의 판단, 사용자 확인 전)

- **연회비 꼬리표 금액:** annual_fee × months / 12를 원 단위로 반올림한다. 엔진은 정확한 값을 빼고, 11개월이면 13,750원으로 나누어떨어진다.
- **받은 혜택 실패:** 받은 혜택 부분도 따로 '결산을 불러오지 못했어요'와 '다시 시도'를 둔다. 놓친 혜택이 오면 그것만이라도 보여 준다.
- **앱 제한 시간:** 두 호출 모두 `AI_CHAT_TIMEOUT_MS`(25초)를 쓴다. 맞춤 추천 페이지와 하루 배치가 쓰는 값이다.
- **카드 그림과 신청 주소 찾기:** 이름 → `CARD_CATALOG_40` → code → `officialProduct(code)` 순서로 찾는다. DB 카드 이름 40개가 앱 카드 목록 이름과 모두 같은 것을 확인했다.
- **설정 메뉴 설명:** 설정 메뉴의 '연말 결산' 설명('올해 아낀 금액·놓친 금액과 월별 추천 기록', `MainScreen.js:759`)도 홈 타일과 같이 '올해 받은 혜택과 놓친 혜택을 확인해요'로 바꾼다.
- **엔진 사본:** 엔진은 `~/Desktop/solpay/solpay-ai`(ai/placement-engine)에서 고친 뒤, 같은 내용을 `solpay-final/solpay-ai` 사본에 맞춘다. 지금 두 사본의 recommend.py와 service.py는 같다.
- **확인 방식:** 화면 확인은 따로 띄운 포트(엔진·백엔드)에서 한다. 사용자 서버(8031/8090/8081)는 끄지 않는다. 커밋과 푸시는 요청받을 때만 한다.

## 만드는 사람에게 맡기는 것

- 쿼리 방식(네이티브 group by 두 번이든, 한 번 읽어 Java에서 묶든). 단, 홈 '최근 결제'와 같은 조건이어야 한다.
- 막대를 그리는 방식(View 높이로 충분하다. 차트 라이브러리를 새로 넣지 않는다).
- 스타일 세부(간격·글자 크기). 지금 앱의 남색·파랑 계열과 둥근 흰 카드를 따른다.

## 방법 비교 (사용자가 방법 1을 고름)

1. **백엔드가 받은 혜택, AI가 놓친 혜택 (채택).** 기록값을 쓰니 홈 숫자와 같고, AI 실패와 따로 보여 줄 수 있다. API가 2개 늘어난다(엔진 인자 1개, 백엔드 1개 + 인자 1개).
2. **AI 엔진이 둘 다.** 앱은 한 번만 부르면 된다. 하지만 엔진 결제 데이터에 결제별 혜택 금액이 없어 읽기 코드를 바꾸거나 다시 계산해야 하고, 다시 계산하면 홈 숫자와 어긋날 수 있다.
3. **앱이 최근 결제를 여러 번 불러 더하기.** 1년 결제가 1,600건쯤이라 30번 넘게 불러야 해서 뺐다.
