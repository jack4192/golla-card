# 바탕화면 웹앱 아침 일정 알림 (웹 푸시) 설계

2026-11-25 · 대상: final (Amplify 웹앱 + EC2 백엔드 + 공용 RDS)

## 왜

아이폰 바탕화면 웹앱(PWA)에도 휴대폰 앱처럼 아침에 "오늘 일정을 알려 달라"는 알림이 오게 한다. 발표 시연에서 여러 사람이 차례로 **같은 알림을 눌러 일정 관리로 들어가 보는 것**까지 보여 주는 게 목적이다.

## 사용자가 정한 것

- 언제: **매일 오전 7시(한국 시간) 자동 + 앱의 '지금 알림 받기' 버튼**
- 어디서 보내나: **백엔드(Spring Boot)** — 회원·알림 동의가 이미 있다
- 문구(추천 안):
  - 제목 `좋은 아침이에요! 오늘은 어디 가세요?`
  - 본문 `일정을 알려 주시면 가는 곳마다 혜택 큰 카드를 미리 골라 둘게요.`
- 알림을 눌러도 알림이 남아 있어야 한다 (다음 사람이 또 누를 수 있게)

## 목표 / 하지 않을 것

- 목표: 웹앱에서 알림 허락 → 매일 7시 알림 → 누르면 일정 관리 화면. 버튼으로 바로 받기. 누른 뒤에도 알림이 다시 보이기.
- 하지 않음: 일정·혜택 내용을 넣은 맞춤 알림, 오프라인 캐시(금융 정보라 캐시하지 않음), 외부 알림 서비스.
- 깨지면 안 되는 것: 알림 동의를 하지 않은 사람에게 보내기, 같은 사람에게 하루 여러 번 보내기(팀원 로컬 백엔드가 같은 RDS를 볼 때), 휴대폰 앱(Expo Go) 알림.

## 제약

- 아이폰: iOS 16.4 이상, **홈 화면에 추가한 웹앱**에서 버튼을 눌러 허락해야 한다. 사파리 탭에서는 안 된다.
- 아이폰은 누른 알림을 지운다 → 누르는 순간 **같은 알림을 다시 띄운다**. 실제 아이폰에서만 확인 가능. 안 되면 '지금 알림 받기' 버튼이 대신한다.
- 백엔드는 자동 배포가 아니다 (EC2에서 직접 다시 빌드). 공용 RDS 표 추가는 마스터 계정이라 사용자가 실행한다.
- 백엔드 DB 검사가 `ddl-auto: validate` 라, 표가 없는 DB에서 백엔드가 안 뜨는 일이 없게 한다.

## 검토한 방법

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 백엔드(Spring)에서 보내기 | 동의·로그인과 한곳, EC2 에 이미 있음 | 웹 푸시 암호화 코드 필요, EC2 다시 빌드 | **팀 선택** |
| AI 서버(FastAPI)에서 보내기 | 파이썬 라이브러리가 간단 | 동의는 백엔드에 있어 둘을 이어야 함 | — |
| 외부 알림 서비스 | 서버 코드가 적음 | 새 계정, 기기 정보가 바깥에 저장 | — |

## 설계

### 백엔드

- 표 `push_subscriptions` (id, user_id → users 삭제 시 함께 삭제, endpoint 고유, p256dh, auth, created_at, last_sent_at). SQL 은 `backend/shared-db/add_push_subscriptions.sql`(공용 RDS, 사용자 실행), `backend/local-db/backend_additions.sql` 에도 추가.
- 표는 JPA 엔티티가 아니라 JdbcClient 로 다룬다 → 표가 없는 DB 에서도 백엔드는 뜨고, 알림 기능만 안내 오류를 낸다. *(내 결정)*
- API (로그인 필요, 공개 키만 예외)
  - `GET /api/push/public-key` → `{ publicKey }` (VAPID 공개 키, 없으면 `enabled:false`)
  - `POST /api/push/subscriptions` `{ endpoint, keys:{p256dh, auth} }` → 내 기기로 저장 (같은 endpoint 면 덮어씀)
  - `DELETE /api/push/subscriptions` `{ endpoint }` → 지움
  - `POST /api/push/test` → 내 기기들에 아침 알림을 **5초 뒤** 보냄 (누르고 홈 화면으로 나갈 시간) *(내 결정)*
- 매일 7시: `@Scheduled(cron = "0 0 7 * * *", zone = "Asia/Seoul")`, `users.notification_agreed = true` 이고 기기가 있는 사람에게. **`PUSH_MORNING_ENABLED=on` 일 때만** 돈다(EC2 만 켬) → 팀원 로컬 백엔드가 같은 RDS 를 봐도 여러 번 가지 않는다. *(내 결정)*
- 보내기: JDK 기본 암호화로 RFC 8291(aes128gcm) 암호화 + VAPID(RFC 8292, 기존 jjwt 로 ES256 서명), `java.net.http.HttpClient` 로 POST. 응답 404·410 이면 그 기기를 지운다. 새 라이브러리 없음. *(내 결정 — RFC 8291 부록의 시험값으로 검증)*
- 설정(환경 변수): `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`(웹앱 https 주소), `PUSH_MORNING_ENABLED`. 키는 한 번 만들어 EC2 `.env` 에만 둔다(깃에 안 올림).

### 앱 (웹에서만, 휴대폰 앱은 그대로)

- `frontend/public/sw.js`: `push` → 알림 표시(tag `morning-schedule`, 누르면 `/?open=schedule`). `notificationclick` → 웹앱을 열거나 앞으로 가져오고, **같은 알림을 다시 띄운다**.
- 앱 시작 때 서비스 워커 등록. `?open=schedule` 로 열리거나 서비스 워커가 메시지를 보내면 기존 아침 알림 흐름(`morningSchedulePending`)으로 일정 관리를 연다.
- 설정 '폰 알림 받기' 토글이 웹앱에서도 동작: 켜면 알림 허락 → 구독 → 백엔드 저장 + 알림 동의 저장. 끄면 구독 해제 + 삭제 + 동의 끔.
  - 사파리 탭처럼 안 되는 곳에서는 "홈 화면에 추가한 앱에서 켤 수 있어요" 안내.
- 토글 아래 **'지금 알림 받기'** 버튼(켜져 있을 때만): 누르면 "5초 뒤 알림이 와요. 홈 화면으로 나가 보세요" 안내.
- 휴대폰 앱(Expo Go) 7시 알림 문구도 같은 문구로 맞춘다. *(내 결정)*

### 시험

- 백엔드: RFC 8291 부록 A 시험값으로 암호화가 같은 결과인지, VAPID 서명 검증, 구독 저장·삭제, 동의 안 한 사람 제외, 404·410 기기 삭제, 7시 예약이 꺼져 있으면 안 보냄.
- 앱: 서비스 워커 메시지·주소 처리 순수 함수 시험, 데모 모드 웹에서 토글·버튼 화면.
- 실제 보내기: 사본 DB + 로컬 백엔드 + 가짜 푸시 서버(받은 내용을 시험 키로 풀어 봄)로 끝까지 확인.
- 실기기(아이폰): 배포 뒤 사용자가 확인 — 알림 허락, 지금 받기, 누르면 일정 관리, 누른 뒤 알림 다시 보이는지.

### 배포 순서

1. 공용 RDS 에 `add_push_subscriptions.sql` 실행 (사용자)
2. EC2 `.env` 에 VAPID 키·`PUSH_MORNING_ENABLED=on` 추가 → 최신 final 받아 백엔드 다시 빌드 (사용자 허락 뒤 내가 SSH 로, 또는 팀원)
3. final 푸시 → Amplify 자동 배포. 배포된 `/sw.js` 가 index.html 이 아니라 자바스크립트로 오는지 확인
4. 아이폰: 웹앱 다시 열기(필요하면 홈 화면에 다시 추가) → 설정에서 '폰 알림 받기' 켜기 → '지금 알림 받기'

## 빌더에게 맡기는 것
