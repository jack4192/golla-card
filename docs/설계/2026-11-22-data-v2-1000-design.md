# 가상 소비 데이터 v2 (1005명·1년) 설계

작성 2026-11-22. 사용자와 질문으로 정한 결정을 정리한다.

## 왜

사용자마다 전체 데이터가 아니라 **직업·나이대가 비슷한 사람들의 데이터로 학습**해 보려 한다.
지금 365명으로는 직업×나이대 칸이 15명 안팎인 곳이 있고(야근 20·30대, 재택 30·40대), 나이가 소비에 영향을 주지 않아
나이대로 묶어도 차이가 생기지 않는다. 그래서 사람이 더 많고, 직업과 나이대가 모두 소비에 드러나는 v2 데이터를 만든다.

## 목표 / 비목표 / 실패 조건

- 목표
  - 배경 1000명 + 데모 5명 = 1005명, 2025-11-01 ~ 2026-11-05 10:00 (v1과 같은 기간)
  - 직업 10개 × 나이대 20~60대, 26칸, 모든 칸 30명 이상
  - 같은 직업 안에서도 나이대마다 업종 비중·건당 금액이 다르다
  - 데모 5명의 카드를 현실적인 3~5장으로 바꾼다
  - 결과물: 엔진·학습용 parquet(`data/out_v2`)과 팀 DB 형식 폴더(`카드서비스_DB_1년_v2` + zip)
- 비목표
  - 엔진·챗봇·FastAPI 가 v2 를 읽게 바꾸는 일 (따로 한다)
  - 로컬·RDS Postgres 적재 (적재 가능 여부만 임시 DB 로 확인하고 지운다)
  - 커밋 (요청 시)
- 실패 조건 (돌아가도 실패로 본다)
  - v1 데이터(`data/out`, `카드서비스_DB_1년`)가 한 바이트라도 바뀐다
  - 팀 DB 표 형식(23표의 칼럼·제약)이 v1 과 달라진다
  - 30명 미만인 칸이 생긴다
  - 나이대별 차이가 결과 데이터에서 보이지 않는다

## 방식

| 안 | 내용 | 판단 |
|---|---|---|
| A. 같은 코드 + v2 설정 겹쳐 쓰기 | `config/v2/*.yml` 에 바꾸는 값만 두고 기본 설정 위에 덮어쓴다. `--version v2` 로 실행하면 결과는 `out_v2` 로 | **채택**. 생성 방식이 v1 과 같고, v1 결과는 그대로 재현된다 |
| B. 생성기 복사본 | `generate_v2` 패키지를 따로 둔다 | 같은 코드가 두 벌이 되어 고칠 때 어긋난다 |
| C. 기존 설정 직접 수정 | v1 설정을 바꿔 다시 만든다 | 지금 데이터를 그대로 두라는 요구와 맞지 않는다 |

사용자가 방법은 맡겼으므로 A 로 한다 (내 결정).

### 새 직업 소비 패턴 (가정값, 팀 확인)

- 자영업자: 가게가 집 동네. 오전 마트·슈퍼 장보기, 점심·저녁은 가게 근처 음식점·배달, 퇴근 21~22시, 건당 금액 1.2배, 차량 70%. KB Biz Prime(사업자 카드)은 이 직업에만 배정.
- 교대근무(간호·생산직): 주마다 주간·저녁·야간 근무가 돌아가며 결제 시간대가 바뀐다. 야간 주에는 심야 편의점·배달이 많다. 직장 동네는 가산·판교·신촌·강남.
- 영업·외근직: 평일 점심·오후에 여러 동네를 돌아다닌다. 주유·주차·카페·음식점이 많고 저녁 음식점 금액이 크다(접대). 차량 95%, 광역교통 60%.
- 은퇴자(60~64세): 출근 없음, 오전·낮 위주. 병원·약국·슈퍼·제과가 많고 배달·온라인은 적다. 하루 2.0건, 골프 20%, 차량 60%.
- 전업주부(40~60대): v1 '출근 없는 50대'(HOME50, 데모 3) 패턴 그대로 + 나이대 효과.

## 구현하며 정한 것 (사용자에게 알림)

- 데모 5명에게는 나이대 효과를 얹지 않는다 (월 지출 197·88·212·123·146만 원 유지).
- 모두의카드를 새로 갖는 데모 1·2·4는 그 카드를 K-패스 등록 카드이자 교통 대표 카드로 둔다. 데모 5는 v1 그대로.
- 데모 3의 직업 코드는 HOMEMAKER(전업주부)로 바꾸되 소비 패턴은 HOME50 과 같다.
- 시드는 v1 과 같다. 사용자마다 난수를 따로 쓰므로 v1 과 같은 번호의 사용자라도 카드·유형이 달라 결제는 다르다.
- 차량 보유는 직업별 비율에 나이대 배율을 곱한다: 20대 0.6배, 30~50대 1.0배, 60대 0.9배 (20대 직장인이 차를 50% 갖는 문제).
- 새 직업의 카드 고르는 습관: 자영업자·영업·은퇴자·전업주부는 업종마다 늘 쓰는 카드(1번 카드 30~50%), 교대근무는 주 카드 몰아 쓰기.
  신용카드 가중치는 자영업자 1.3, 영업 1.2, 은퇴자·전업주부 1.2, 교대근무 1.0.
- 아파트 관리비는 맞벌이·전업주부·은퇴자·자영업자가 낸다.

## 빌더에게 맡기는 것 (구현 메모)

- 설정 겹쳐 쓰기: `common.load_config(name)` 이 v2 일 때 `config/v2/{name}.yml` 을 기본 설정 위에 깊게 합친다 (사전은 합치고 목록은 바꿔 끼움). `OUT_DIR` 도 `out_v2`.
- `population.yml`(v2): `cells`(직업·나이대·인원)와 `card_count`(집단별 장수 분포)를 새로 두고, 있으면 `archetype_share`·`extra_users` 대신 쓴다.
- `distributions.yml`(v2): 새 직업 5개, `age_effects`(나이대별 업종 배율·금액 배율·학원비 비율·차량 배율), 특수 결제 소유 비율에 새 직업, 심야 배율.
  교대근무는 `shift_rotation`(주간·저녁·야간 시간대 비율과 출퇴근 시각)을 두고 주 번호 + 사용자별 시작 위치로 고른다.
  영업·외근직은 `roam_slots`(평일 점심·오후)에 회사 동네 대신 동네 후보 중 하나를 고른다.
- `personas.yml`(v2): 새 직업의 카드 고르는 습관, 데모 5명 목록(통째로 바꿈, `added_cards` 없음).
- `card_db_map.yml`(v2): 발급 자격에 KB_BIZ_PRIME → SELFEMP.
- `export_db`: 결과 폴더·parquet 위치를 v2 로, 60대 나이(60~64), 새 직업의 직장명, 데모 카드 중 v1 원본 행과 같은 카드는 끝 4자리·목표 구간을 그대로, 새 카드는 생성 값.
  `schema.sql`·`load_all.sql`·`테이블_명세서.csv`·`테스트_가이드.md` 는 v1 폴더 사본에서 가져와 설명 주석·인원·데모 카드 안내만 고친다.
- 검증
  - v1 을 다시 만들어 `data/out/parquet` 가 바이트까지 같은지, data 테스트 통과
  - v2: 1005명, 26칸 모두 30명 이상, 데모 카드 일치, 카드 수 분포·평균, 발급 자격·묶음·신한 1장·타사 60%
  - 월 지출 분포(전체 하위 10%·중앙·상위 10%)와 칸별 중앙값, 같은 직업 안 나이대별 병원·배달 비중 차이
  - 데모 5명 월 지출이 v1 과 비슷한지
  - 팀 DB v2 폴더를 임시 Postgres DB 에 가이드 순서대로 적재해 행 수 대조 후 지운다
