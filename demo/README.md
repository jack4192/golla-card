# SOL페이 AI 카드 배치 데모

결제화면을 열면 AI 추천 엔진(solpay-ai)이 카드 순서와 안내 문구를 정하고, 고객이 고른 카드로 일회용 코드를 발급해 가상 POS에서 결제하는 데모입니다.
**실제 카드·결제망·신한 서버와 연결되지 않습니다.** 카드 이름과 혜택은 가상 데이터의 임의 값입니다.

## 구조

실제 서비스의 `앱 → Spring → FastAPI 추천 엔진` 구조를 그대로 따릅니다. 이 데모 서버가 Spring 역할을 합니다.

```
가상 POS(/pos)  ── 카메라로 앱 QR·바코드 찍기
        │
        ▼
데모 서버 (demo/, 포트 8000)  ── 토큰 발급, POS 승인, 거래 저장
        │  HTTP, 카드 순서는 0.8초 제한
        ▼
AI 추천 엔진 (solpay-ai, 포트 8001)  ── 카드 순서, 문구, 실적, 혜택 계산
```

AI 엔진이 꺼져 있거나 0.8초 안에 답하지 않으면 결제화면은 기본 순서로 열리고, 결제는 그대로 승인됩니다.

## 실행

[uv](https://docs.astral.sh/uv/getting-started/installation/) 가 필요합니다. 저장소 루트에서 아래 한 줄이면 가상 데이터 생성(처음 한 번), AI 엔진, 데모 서버가 모두 켜집니다. Ctrl+C 로 함께 꺼집니다.

```bash
./run_demo.sh
```

직접 켜려면 터미널 두 개를 씁니다. 처음이면 solpay-ai README의 "처음 실행"을 먼저 따라 합니다.

```bash
cd solpay-ai
uv run uvicorn engine.api:app --port 8001
```

```bash
cd demo
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

- 가상 POS: http://localhost:8000/pos (주소 맨 앞 / 로 들어와도 POS 로 간다)
- 결제 데모 화면(/pay)은 2026-11-24 에 뺐다. 결제 코드는 SOL·Pay 앱의 QR 결제 창에서 만든다.
- API 문서: http://localhost:8000/docs

AI 엔진을 다른 주소나 포트로 켰다면 `SOLPAY_AI_URL` 로 알려 줍니다.

```bash
SOLPAY_AI_URL=http://127.0.0.1:8000 uvicorn app.main:app --port 8001
```

### SOL·Pay 앱 결제와 잇기 (2026-11-24)

단말기 키가 있는 가맹점은 가상 POS 가 승인 요청을 SOL·Pay 백엔드(`/api/v1/pos/payments`)로 보낸다. 이때 가맹점 목록에는 키가 있는 가맹점만 나온다. 키가 하나도 없으면 예전처럼 이 데모 서버가 발급한 코드만 승인한다.

**1) 시연용 단말기 만들기 (처음 한 번).** DB 의 단말기는 키 원문을 저장하지 않으므로(가상 데이터 660개도 원문 없음) 키를 아는 단말기를 새로 넣는다.

```bash
cd demo
python -m app.terminals 560        # 560 = 스타벅스 강남역점. 키는 demo/data/terminal_keys.json 에 저장(git 에 안 올라감)
```

화면에 나온 SQL 을 백엔드가 쓰는 DB 에 실행한다. 로컬 DB 는 `docker exec -i solpay-db psql -U solpay_app -d solpay_v21`, 공용 RDS 는 마스터 계정으로 실행한다. 키 파일 대신 `SOLPAY_FIXED_TERMINAL_KEYS='{"560":"<키>"}'` 환경 변수로 줘도 된다(이쪽이 먼저).

**2) 가상 POS 켜기.** 백엔드를 8080 이 아닌 포트로 켰다면 `SOLPAY_BACKEND_URL` 로 알려 준다. AI 엔진에 토큰을 걸었다면 `SOLPAY_AI_TOKEN` 도 같은 값으로.

```bash
SOLPAY_BACKEND_URL=http://127.0.0.1:8090 SOLPAY_AI_URL=http://127.0.0.1:8031 uvicorn app.main:app --port 8000
```

키 파일·환경 변수는 요청마다 읽으므로 단말기를 새로 만들어도 POS 를 다시 켤 필요가 없다.

### 카메라로 찍기

승인 요청 아래 "카메라로 QR·바코드 찍기" 를 누르면 카메라로 QR·Code128 을 읽어 번호를 채우고 바로 승인 요청을 보낸다. 브라우저에 BarcodeDetector 가 없으면 ZXing(jsDelivr)을 불러오므로 인터넷이 필요하다. 카메라는 localhost 또는 https 에서만 켜진다 (Claude 앱 안 브라우저는 카메라를 막으므로 크롬 등 일반 브라우저로 연다).

## 시연 순서

1. **상황 고르기:** 결제 화면 위쪽 "시연 조건"에서 데모 사용자와 시연 시각을 고릅니다. 예를 들어 데모 사용자 1, 목 12:20 점심입니다. 위치(GPS)는 쓰지 않습니다.
2. **아침 알림:** 휴대폰 잠금 화면에 "오늘 일정을 알려주세요" 알림이 뜹니다. 알림을 누르면 SOL페이가 열립니다. "아침 알림부터 다시"를 누르면 언제든 이 화면으로 돌아옵니다.
3. **하루 일정 입력:** 시간 범위(예: 12:00~14:00), 업종, 예상 금액만 넣습니다 (최대 10줄). 줄마다 "가게 이름" 칸에 "스벅", "올리브영", "헬스장"처럼 쓰면 AI 엔진이 업종·가맹점을 분류해 칩으로 보여 주고 업종과 예상 금액을 채웁니다 (가맹점·별칭 검색이 먼저, 못 찾으면 OpenAI. 여러 곳이면 후보 버튼). 분류된 가맹점(브랜드)도 일정에 저장되어 그 브랜드의 혜택·행사로 추천합니다. 입력한 글은 저장하지 않습니다. "일정 없음 · 건너뛰기"를 누르면 일정 없이 평소 소비 패턴과 실적으로 카드 순서를 정합니다. 일정은 시작 30분 전부터 끝난 뒤 30분까지 적용됩니다.
4. **맞춤 추천 페이지 (2026-11-23부터):** 일정을 저장하면 AI 엔진의 맞춤 추천 페이지를 받아, 카드 탭은 '카드를 추천해드려요' 화면에, 가맹점 탭은 일정 맞춤 프로모션 화면에 보여 줍니다(둘 다면 카드 → 프로모션). 아래는 예전 일정 팝업의 규칙이며 서버의 `/api/schedule-popup` 은 남겨 두었습니다. 일정을 저장하면 팝업이 뜹니다. 마지막 카드 추천에서 3일이 지났으면 한 달 3,000원 이상(연회비 반영) 더 받을 수 있는 신한카드를 추천하고, 그 외의 날에는 일정 업종에 맞는 프로모션을 최대 2건 보여 줍니다. 프로모션을 보여 준 일정 시간(시작 30분 전 ~ 끝 30분 후)에는 그 프로모션을 받으면서 건당 혜택이 가장 큰 신한카드가 결제 화면 1순위가 됩니다. 둘 다 없으면 바로 결제 화면으로 갑니다. "카드 신청"은 시연용이라 실제로 신청되지 않습니다.
   - 예: 데모 사용자 1, 목 08:30, 14:00~15:00 카페 6,000원 → "메가MGC커피 500포인트 + Discount Plan+ 10% 600원 = 약 1,100원". 시연 시각을 14:10으로 바꾸면 Discount Plan+가 1순위로 나옵니다.
5. **AI 추천 확인:** 결제 화면 위에 오늘 일정과 계산 방식("오늘 일정에 맞춤" 또는 평소 소비 패턴)이 나오고, AI 1순위 카드와 안내 문구가 나옵니다.
6. **판단 근거 확인:** 오른쪽(좁은 화면에서는 아래)에 다음 정보가 나옵니다.
   - **AI 판단 근거:** 계산 방식, 예상 결제, 카드별 원화 점수
   - **이번 달 카드 실적:** 다음 구간까지 남은 금액, 받은 혜택
7. **결제:** 가상 POS에서 가맹점과 금액을 확인하고 결제 화면의 18자리 번호를 넣어 승인합니다. 결제 화면이 "결제 완료"로 바뀌며 이번 결제 혜택과 가장 유리했던 카드를 보여 줍니다.
8. **결제 후 변화:** "확인"을 누르면 결제가 반영된 실적과 한도로 카드 순서를 다시 받습니다.
9. **연말 결산 미리보기:** 오른쪽 "연말 결산 미리보기"에서 "계산하기"를 누르면, 지난 1년 동안 그 신한카드가 있었다면 더 받았을 혜택(상위 3장)을 보여 줍니다.
10. **규칙:** "내 규칙"에서 규칙을 추가하면 다음 결제화면부터 적용됩니다. 예를 들어 "지금 요일·시간대에는 이 카드", "실적보다 건당 혜택 우선"이 있습니다.
11. **초기화:** "시연 초기화"를 누르면 시연 중 쌓은 결제·규칙·일정·카드 추천 기록을 지우고 처음 상태로 돌아갑니다.

시연 시각 프리셋:

| 프리셋 | 보여 줄 수 있는 것 |
| --- | --- |
| 목 08:10 출근길 | 아침 시간대 패턴 |
| 목 12:20 점심 | 평일 점심 반복 구간, 음식점 혜택 카드 |
| 목 19:10 퇴근 후 | 저녁 업종이 흩어질 때 (카드는 항상 1장) |
| 토 14:30 주말 오후 | 주말 동네 소비 |
| 11/30(월) 12:20 월말 점심 | 월말 실적 달성 압박이 커질 때의 실적 교체 |

## 파일

```
app/main.py   페이지와 API (시연 설정, 결제화면 구성, 토큰, POS 승인, 규칙, 거래내역)
app/ai.py     AI 엔진 HTTP 호출 (카드 순서는 0.8초 제한, 실패하면 기본 순서)
app/demo.py   데모 사용자 5명, 시연 시각, 동네 이름
app/db.py     SQLite: 시연 설정, 토큰, 거래 내역
app/codes.py  토큰 → Code128 바코드, QR(SVG)
static/       pay.html(결제 화면), pos.html(가상 POS), style.css
tests/        가짜 AI 서버로 도는 테스트, 실제 엔진과 끝까지 도는 테스트
data/app.db   실행하면 생기는 DB (SOLPAY_DB 환경변수로 위치 변경)
```

| API | 하는 일 |
| --- | --- |
| `GET /api/me` | AI 가 정한 카드 순서, 문구, 오늘 일정, 판단 근거, 카드별 실적, 규칙 |
| `GET /api/demo/options` | 데모 사용자, 시연 시각, 동네별 가맹점(가상 POS용), 일정 업종 |
| `GET·PUT /api/demo/state` | 현재 시연 설정 (사용자, 시각) |
| `GET·PUT /api/schedule` | 시연 날짜의 하루 일정 조회·저장 (시간 범위·업종·예상 금액만, 빈 목록이면 지움) |
| `POST /api/schedule-popup` | 일정 저장 뒤 팝업. `kind`: card(새 카드) / promotion(일정 맞춤 프로모션) / none |
| `POST /api/card-recommendation` | (이전 방식) 새 카드 추천. 추천할 카드가 없으면 `recommend: false` |
| `GET /api/missed-benefit` | 연말 결산 미리보기 (지난 1년 동안 더 받았을 혜택, 상위 3장) |
| `POST /api/demo/reset` | 시연 초기화 |
| `POST /api/tokens` | 선택한 카드로 일회용 토큰 발급 (바코드·QR 포함) |
| `GET /api/tokens/{token_id}` | 토큰 상태와 결제 결과 (혜택, 가장 유리했던 카드) |
| `POST /api/pos/approve` | 가상 POS 승인. 승인되면 AI 로 혜택을 계산하고 결제를 AI 에 보냄 |
| `POST /api/rules`, `DELETE /api/rules/{index}` | 사용자 규칙 추가·삭제 (챗봇 대신 간단 입력) |
| `GET /api/transactions` | 승인·거절 시도 전체 내역 |
| `GET /api/health` | 데모 서버와 AI 엔진 연결 상태 |

## 테스트

```bash
python -m pytest -q
```

`demo` 폴더에서 실행합니다. 가짜 AI 서버로 결제 흐름, AI 순서, AI 장애 시 기본 순서, 혜택 계산, 규칙, 초기화를 검사합니다.

실제 AI 엔진과 끝까지 돌려 보려면 저장소 루트에서 solpay-ai 의 가상환경으로 실행합니다.

```bash
cd solpay-ai && PYTHONPATH=../demo SOLPAY_AI_DIR=$PWD uv run --with segno --with python-barcode python -m pytest -q --rootdir ../demo ../demo/tests/test_with_engine.py
```

## 토큰 보안 규칙 (예전 MVP 와 같음)

- 18자리 난수(`secrets`), 유효시간 60초 (`TOKEN_TTL_SEC`)
- DB에는 원문 대신 HMAC-SHA256 해시만 저장. 비밀키는 `SOLPAY_SECRET` 환경변수, 없으면 실행마다 새로 생성(재시작 시 기존 토큰 무효)
- 1회 사용: 조건부 UPDATE로 동시에 두 번 찍어도 하나만 승인
- 새 코드를 받으면 이전 미사용 코드는 즉시 무효(REVOKED)
- 실제 카드번호는 받지도 저장하지도 않음. 카드의 끝 4자리도 가짜 값

## 알아 둘 점

- 시연에서 쌓은 결제는 AI 엔진의 메모리에만 들어갑니다. AI 서버를 다시 켜면 가상 데이터 상태로 돌아가므로, 그때는 "시연 초기화"로 데모 서버 기록도 함께 지웁니다.
- 위치(GPS)는 받지도 엔진에 보내지도 않습니다. 하루 일정은 엔진 메모리에만 있고 그날이 지나면 지워집니다 (운영 DB 에서는 암호화해 저장).
- 규칙은 챗봇 대신 정해진 문장으로 만듭니다. 챗봇은 아직 포함하지 않았습니다.
- 가상 데이터는 2026-11-05 10:00 까지 있습니다. 시연 시각은 그 이후로 고르는 것이 자연스럽습니다.
